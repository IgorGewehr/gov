# W9.1 — Migration pendente (gerar na fase verify com ~/.dotnet8)

A configuracao EF do agregado `Contrato` (`ContratoConfiguration`) ganhou TRES colunas novas na tabela
`Contratos` (schema `administracao`). E necessario gerar uma migration antes do verify.

## Colunas adicionadas
- `DataAssinatura` (date, NOT NULL) — marco inicial do prazo PNCP (art. 94). Default p/ linhas legadas:
  pode usar a `VigenciaInicio` (a config gera NOT NULL; em SQLite/SqlServer a migration deve definir um
  default ou popular via UPDATE no `Up`).
- `PublicacaoPncpVencida` (bit/INTEGER, NOT NULL, default 0) — intempestividade da divulgacao.
- `PrazoPublicacaoPncp` (nvarchar(120), NULL) — VO `PrazoPncp` serializado
  (`"{tipo}|{dataAssinatura:O}|{quantidade}|{unidade}|{dataLimite:O}|{normaFonte}"`).

## Comando (EF tool e net8 — usar o SDK 8 dedicado)
```bash
~/.dotnet8/dotnet ef migrations add W91PncpPrazoEficacia \
  --project src/Modules/Administracao/Tensorroot.Gov.Modules.Administracao.Infrastructure \
  --startup-project src/ApiHost \
  --context AdministracaoDbContext
```

> Observacao: o restante do build/test roda com o SDK default (.NET 10, roll-forward). Apenas o
> `ef migrations add` usa o `~/.dotnet8` (o EF tool e net8).

## Conferir no `Up` gerado
- `DataAssinatura` NOT NULL: se houver linhas legadas, popular com `VigenciaInicio` antes de aplicar o
  NOT NULL (ou gerar com `defaultValueSql`).
- `PrazoPublicacaoPncp` NULL (legados sem prazo continuam validos; o codigo trata `PrazoPublicacaoPncp is null`).
